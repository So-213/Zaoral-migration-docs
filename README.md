# Zaoral 移行計画ドキュメント

Zaoral(Next.js単体構成のLP作成SaaS)を、**フロントエンド(Next.js)とバックエンド(Spring Boot)に分離する**移行計画と、その過程での決定記録。

スピード優先ではなく、ステップとドキュメントを明確にしながら安全に仕組み化して進めることを方針としている。

## 入口

**[移行計画書.md](./移行計画書.md)** — 目的・ゴール・ステップ一覧・スコープ。**まずここを読む。**

ステップ一覧の表に各ステップの状態(完了/未着手)が記載されており、現在地はそこで確認できる。

## 対象リポジトリ

| リポジトリ | 役割 | 本計画での扱い |
|---|---|---|
| [Zaoral](https://github.com/So-213/Zaoral) | 現行の本番稼働プロジェクト | **変更しない**(コピー元としてのみ参照) |
| [Zaoral-frontend](https://github.com/So-213/Zaoral-frontend) | 分離後のフロントエンド | 移行対象 |
| [Zaoral-backend-springboot](https://github.com/So-213/Zaoral-backend-springboot) | 分離後のバックエンド | 新規作成 |

`Zaoral_backend2` / `Zaoral_backend3` は移行対象外。

## 運用ルール

- ステップごとに番号付きファイルを作成し、「やったこと」「決定事項」「懸念点・持ち越し事項」を残す。
- ステップの状態が変わったら[移行計画書.md](./移行計画書.md)のステップ一覧を更新する。
- 解消しない懸念は各ファイルの「申し送り」に書き、次ステップへ引き継ぐ。
- **仕様判断を変更した場合は、コード側の変更と併せてこのリポジトリも更新する**(別リポジトリであるため乖離しやすい点に注意)。
